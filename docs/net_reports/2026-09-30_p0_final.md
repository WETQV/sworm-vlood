## Двойное и пропущенное применение (сценарий `integrity`)

Манекен с огромным HP и без i-frames (чтобы правила игры не маскировали сетевые ошибки). Каждый игрок бьёт его 15 раз; клиенты затем шлют 20 запросов в обход кулдауна и повтор уже принятого номера. Хост убивает манекен — смерть должна прийти ровно один раз на каждый процесс.

| Проверка | Результат (итоговая матрица 2/3/4 игрока × 3 профиля + 4 повтора 200 мс/3% после исправления снарядов) |
| --- | --- |
| Принято хостом = попаданий, у каждого игрока | 25 из 27 строк матрицы; 2 несовпадения (200 мс/3%) — пролёт снаряда, исправлено; после исправления 14 из 14 строк |
| Урон | Точно по оружию: мечник 15 × 25, лучник × 20, маг × 35, паладин × 38 |
| Смерть манекена | Ровно 1 на каждом процессе во всех прогонах |
| Спам в обход кулдауна | Отклонён (`attack_rejected_cooldown` 37–60 за прогон); проходят только запросы после истечения кулдауна |
| Повтор принятого номера | Отклонён (`attack_rejected_replay` = числу клиентов) |

## Медленная загрузка, выход игроков и хоста

3 игрока, RTT +100 мс ± 10, 1% потерь, сценарий переходов этажей.

| Сценарий | Результат |
| --- | --- |
| Клиент грузит уровень на 6 с дольше | Хост дожидается; на каждом этаже все трое, ошибок нет |
| Клиент грузит на 30 с дольше (> 20 с) | Через 20 с получает «Уровень не загрузился вовремя…», выходит в меню; двое продолжают (2 перехода) |
| Клиент выходит на подготовке перехода | Хост продолжает вдвоём через ~3.6 с |
| Клиент выходит во время загрузки этажа | Было: хост ждал ~33 с. Стало: продолжение через ~3 с |
| Хост выходит в меню | Было: «Соединение с хостом потеряно». Стало: «Хост завершил игру.», оба клиента в главном меню |
| 10 переходов вчетвером с перезапуском, 200 мс/3% | 0 ошибок, 0 «сирот», число узлов стабильно |

## Согласование точек и времени атак

- **Точка**: хост считает удар/снаряд/волну из точки владельца (`origin`). Расхождение показанного оружия с точкой удара у наблюдателя — 4 px (p50/p95).
- **Время**: наблюдатель проигрывает чужую атаку и события ИИ с задержкой показа тела. Расхождение «тело у наблюдателя ↔ тело владельца в момент удара», бой 4 игроков, RTT +100 мс, два прогона без/с выравниванием: p95 13–14 → 9–12 px, максимум 47–68 → 16–59 px. Для врагов «тело ↔ точка события»: p95 3–15 → 2–3 px. Эффект невелик, т.к. задержка показа при таком джиттере ~30–40 мс, но совпадение теперь по построению.
- **Отбрасывание**: решает хост; владелец применяет его к себе при получении `_net_hit_fx`, остальные видят через снимки.
- **Рывок**: владелец начинает сразу, хост — при приёме; неуязвимость на хосте сдвинута на задержку «владелец → хост». Ограничение хост-авторитета, записано в контракт.

## Реальная LAN (выполняет команда)

Стенд запускает участников на одной машине, поэтому профиль LAN из ТЗ эмулируется. Для проверки на реальных компьютерах (домашняя сеть или Radmin VPN) — `tests/net/lan.ps1`:

```powershell
# на компьютере хоста
powershell -ExecutionPolicy Bypass -File tests/net/lan.ps1 -Role host -Players 2 -Scenario combat
# на компьютере друга (IP хоста — из лобби игры / Radmin VPN)
powershell -ExecutionPolicy Bypass -File tests/net/lan.ps1 -Role client -HostIp <IP хоста> -Players 2 -Scenario combat
```

Порт стенда — 7010 (UDP). Затем клиент отправляет свою папку с логами хосту, хост кладёт её рядом и запускает `python tests/net/analyze.py <папка>`. Часы разных компьютеров выравниваются по пингу (точность ± половина RTT). Рекомендуемый минимум: `walk`, `combat`, `integrity`, `floors -Floors 3`. Проверено на одной машине: скрипт, объединение логов и синхронизация часов работают.
